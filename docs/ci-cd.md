# Перевірка та випуск

Проєкт продовжує варіант 4, систему автопідприємства з ЛР 1-5.
Python 3.12, стандартна бібліотека, зовнішні залежності відсутні.

Конвеєр: push до main / PR до main / ручний запуск; checkout;
Python; compileall; unittest; лише main: ZIP і upload-artifact.
Синтаксична помилка, невдалий тест або помилка пакування завершують CI невдачею.

Локальна перевірка:

```text
python -m compileall -q src tests scripts
python -m unittest discover -s tests -v
python scripts/package_project.py
```

Артефакт `autopark-package` містить `autopark-0.1.1.zip` з кодом,
тестами, документацією, скриптом пакування та workflow. Кеші, `.git`,
локальні середовища та `.env` не входять до переліку пакування.
Завантажений архів можна розпакувати й перевірити тією самою командою unittest.

Git tag `v0.1.1` позначає коміт, а GitHub Release описує випуск.
PATCH підвищено через вдосконалення перевірок і процесу випуску без зміни API.
Артефакт належить запуску Actions і зберігається 30 днів, Release належить версії.

CI реалізовано тестуванням; підготовка ZIP є частиною Continuous Delivery.
Continuous Deployment потребував би автоматичного розгортання у production.
Для майбутньої вебсистеми обрано Blue-Green: два середовища, перевірка нового,
перемикання трафіку, повернення на попереднє при збої. Це потребує додаткових
ресурсів; для бази даних потрібні сумісні міграції. У прототипі розгортання немає.

Для DORA потрібні події production deployment, зв'язок коміту з deployment,
невдалі розгортання та час відновлення. Тривалість CI не є lead time до production.

Workflow має лише `contents: read`. Секрети в коді та логах не зберігаються.
Бажане правило main: зміни через PR та обов'язковий успішний `test`.
Правила захисту репозиторію цим workflow не змінюються.
